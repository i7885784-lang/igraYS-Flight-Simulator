# Проверка сообщения «индикатор есть, но не заполняется»

Изменений исходников и EXE нет. Проверочный полёт использует штатный F-18E, AIM-9, карту OCEAN, команды IFF 0/1, высоту 3000 м и разрыв 1500 м. Обе машины летят прямо на штатном автопилоте; ракета выбрана сохранённой командой WEAPONCH AAM. Цель не атакует. Игровой ZIP сохраняет все файлы v7, добавляет практику и документацию.

Проверки выполнялись в Wine 10 / Xvfb на отдельной Win64 GL1 сборке тех же исходников v7. Готовый PE32 EXE на Windows 10 x86 здесь не запускался. Полный архив проверен на равенство файлов исходной v7, PE32 i386, отсутствие тестового профиля/истории и CRC.

- Обычный физический Space до захвата не расходует боезапас, после 3 секунд расходует одну AIM-9. Программная команда BTNFUNC не использовалась для пуска.
- Проверены сохранённый режим клавиатуры и отдельный профиль с исходными настройками мыши.
- Дополнительно проверен тот же старт без автопилота игрока.
- Через обычный интерфейс открыто «Мои полёты → Открыть старый файл .yfs...», загружены те же байты YFS, запущен полёт, получен зелёный индикатор и произведён пуск. Скриншоты сохранены.

Смотрите JSON и журналы рядом. В каталогах training-v7/practice лежат точные проверочные файлы; в игровой архив входит только первый, под именем practice_v7/lock.yfs. Скрипты проверки рассчитаны на сохранённую среду /workspace/ysflight-work с Wine, Xvfb :99 и инструментами из toolchain. v7-launch.py и исходники находятся в архиве исходников v7.

Первый прогон ввода не прошёл: при одном лишь XSetInputFocus окно Wine не получало удержание клавиши. Проверка была исправлена настоящим кликом для активации окна и удержанием Space 250 мс; это проблема автоматизации без оконного менеджера, изменений игры не потребовалось. Причина сообщения пользователя не установлена: в проверочном полёте симптом не воспроизведён.
