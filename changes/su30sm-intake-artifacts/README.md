# Су-30СМ: посторонняя геометрия во впуске

Отдельная копия последней VisualPolish1a10d466. Новый скриншот воспроизведён в игре. Все узлы/анимации/родители/оси, кабина, сопла и эффекты, материалы/окраска и прочие файлы сохранены. StableCURRENT5 и предыдущие кандидаты не перезаписывались.

Причины: поверхности Fuselage_0_4 и GearWell_Left/Right заходят в существующий воздушный проход; старые передние детали компрессоров Fuselage_0_7/13 перекрывают уже существующие компрессоры IntakeDuct на глубине. Это не внутреннее свечение: C/B не изменялись.

repair.py вычитает только измеренный объём проходов из пяти подтверждённых ресурсов. Плоскости точно получены из четырёх неизменённых стенок IntakeDuct. Для F4 диапазон Z[-3.10,-1.25], для фронтальных старых вентиляторов и облицовок ниш проход продолжен до их передней границы Z-.39. Внешние рамки не перестраиваются. Все старые вершины и нетронутые блоки граней сохраняются; новые треугольники только подмножества исходных треугольников, никакого заполнения/подстановки ближайших высот. Кривые исходные четырёхугольники сначала разбиты по исходному вееру, затем обрезаны. Исходные C/B и прочие атрибуты граней копируются. Материалы не темнеют, двигатель не закрашивается чёрным.

Точная поставка: SourcesZIP уже содержит baseline/su30sm.dnm. Установить requirements.txt, затем `python build.py`. Обе SHA строго проверяются, все узлы и остальные ресурсы буквально прежние. Полный алгоритм `python repair.py`; после новых правок нужны новые проверки.

Проверка: requirements-validation.txt; `validate.py`, `final_motion.py`. subset-provenance.json доказывает принадлежность каждого нового треугольника исходной поверхности, сохранение плоскости и отсутствие перекрытий между фрагментами одного исходного треугольника. Сравнительные PNG, нативные G/движение камеры и параметры — в ReportZIP/reports/su30sm-intake-artifacts. Windows OpenGL64 фактически запущен под Wine; Win32 EXE прежний, повторно не запускался. Это не непрерывное доказательство отсутствия всех пересечений самолёта.

Старый контакт основных колёс с IntakeDuct при уборке и фасеточный вид некоторых исходных панелей остаются; здесь механизм не перестраивается. Подробный результат, ограничения и ссылки — REPORT_RU.md/STATUS.json. Геометрия заморожена для визуальной приёмки.
