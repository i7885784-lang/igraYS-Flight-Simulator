# Су-30СМ №5 — геометрия ниш и створок

Продолжение реально сохранённой рабочей копии после потери среды. Начальный частичный DNM `965b609b60b565649b52ed3b853d9ab7f455bb13c35664a02096f6b2fc69e885` сохранён отдельно в лаборатории. Основа для новой законченной правки — предыдущая проверенная сборка ShutterFix, DNM SHA `86455c587b7d15e59a487b6bcae276713aceafafb7d0e5a2b8672901d5cb4558`. Ни версия5, ни ShutterFix не перезаписываются. Исторические решения6/7 не переносились.

Поменяны только DNM-ресурсы; двигатель игры, физика, управление, моторы, камеры, колёса, стойки, прочие самолёты сохранены. У существующих узлов неизменны родители, классы, POS/CNT и число состояний. Исключение в STA — только небольшое согласование фаз двух MainWheelBayShutter при подтверждённых столкновениях. Все кривые колёс/стоек/внешних дверей точные прежние. Добавленная правая задняя носовая дверь и шарнирные пальцы используют прежние кривые существующих дверей.

- `nose_bay.py`: передняя граница проёма 4,16→4,45м по измеренному ходу колеса, перенос вырезанных окрашенных поверхностей в закрывающие створки. Только низ Fuselage_0_4 внутри X±0,38/Z4,16…4,45. Пол кабины не меняется; потолок ниши Y0,455, ниже пола на25мм. Четыре стенки, полноценный потолок, сохранённое движение.
- `doors.py`: формы по измеренной поверхности, 2мм рабочий шов, небольшие фаски внешних углов; прямая встречная кромка носовых листов, без неподвижных треугольников в центре открытой ниши. Посадочные полосы только по реальному периметру общей ниши, с выборками под пальцы. Корректный общий стык старой и дополнительной поверхности при Z4,16. Замкнутые8мм панели.
- `covers.py`: убраны участки самих крышек, попадавшие в расширенный на20мм объём неизменённых воздушных каналов. Сохранены оси/амплитуда/конечные положения, открытие сдвинуто к g0,12…0,20; закрытие g0,84…1, чтобы не пересекать внешнюю дверь/щиток. Общая последовательность механизма сохраняется.
- `lining.py`: выборки для шарниров в облицовке. Левая основная облицовка исправлена по симметричной правой, которая не мешала исходному движению; это игровая реконструкция, не заводская карта деталей.
- `mounts.py`: видимые корпусные вилки и пальцы закрывают визуальный разрыв при сохранённом70мм технологическом смещении дверей. Попытка просто убрать это смещение вернула пересечения и была отклонена.
- `repair.py`: удаление нулевых/повторных граней, нормали, светлое внутреннее покрытие без свечения, умеренные рёбра и линии гидравлики; все детали привязаны к стенкам/потолку.
- `source-data/upper-closure.srf`: только подтверждённые потерянные верхние фрагменты над основными нишами, из исходной геометрии до gear4, с прежней формулой окраски; происхождение/SHA в соседнем JSON. `extract_upper.py` воспроизводит извлечение из такого исторического промежуточного DNM. Сам большой промежуточный DNM отдельно не вложен; исходный GLB и исторические конвертеры сохранены в полном Sources ZIP.

## Точное повторение поставки

Python3.12, `pip install -r requirements.txt`. В Sources ZIP исходный DNM уже находится в `baseline/su30sm.dnm`. Выполнить `python build.py`: файл будет собран из редактируемых SRF в `patches/` и записей узлов в manifest.json. SHA результата строго проверяется. Это именно проверенный в игре ресурс, а не новая независимая триангуляция на другой платформе.

Полный алгоритм разработки: `python repair.py 2`. Для него нужны baseline, source-data и зависимости. Исходные операции с геометрией сохранены, но побайтная детерминированность повторной триангуляции на всех платформах не обещается. После правки алгоритма или ресурсов нужны повторные проверки; не подменять поставку непроверенной геометрией.

Проверки: `pip install -r requirements-validation.txt`, затем `validate_geometry.py`, `final_motion.py`, `selfcheck_final.py`. Скрипты захвата и одинаковые камеры до/после приложены к Report ZIP. Игра Windows OpenGL64 фактически запускается под Wine; Windows32 заново не проверяется, его EXE остаётся прежним.

Сохраняются ограничения исходной модели, в частности пересечение неизменённых основных колёс с неизменёнными воздушными каналами при исходной укладке. Не объявлять весь Су-30СМ точной заводской копией или полностью свободным от всех пересечений. Подробности и результаты — reports/su30sm-gear-bays-repair/REPORT_RU.md; итоговые ссылки/SHA — STATUS.json.
