# Су-30СМ: тест №2

Продолжение завершённого теста1. Оригинальная модель HappyMexicano7, CC BY4.0: https://sketchfab.com/3d-models/85efcbd199844215a171016429a3b4cd. Исходный GLB, авторство и полная лицензия сохраняются в SourcesZIP, notices и licenses игры. Новые детали и изменения описаны ниже.

Полностью отключено сглаживание поверхности Су30, без децимации. Правые сопловые лепестки заменены зеркальными копиями левых: одна геометрия, pivots и21состояние,32пары. Их диапазон радиуса1:1.35. Внешние коробки шасси0.5м удалены, стойки и укладка изменены, добавлены шарнирные детали. Фонарь открывается до55°, стекло42/255, добавлен простой интерьер. Глаз пилота(0,1.18,5.55). Маленький cockpit DNM не дублирует все94меша и двигатели; кэш его трансформаций обновляется перед рисованием. Прозрачный выхлоп114/115 отделён от форсажного пламени112/113, тёмные горловины одинаковы.

Обзор в кабине универсален для каждого самолёта: удерживать ЛКМ или ПКМ и двигать мышью; двойной Пробел с интервалом до400мс возвращает взгляд вперёд. Пробел в режиме кабины больше не стреляет. Текстовые диалоги сохраняют обработку текста. При обзоре мышиное управление не меняет крен/тангаж, после отпускания курсор восстанавливается; аппаратный джойстик не замораживается. F1 — кабина, F2 — внешний вид. Alt+5 — фонарь на малой скорости/стоянке, G — шасси, Q/A — тяга, Tab — форсаж.

Один GameZIP содержит обе архитектуры и всех самолётов теста1. Play_Su30SM.bat выбирает32/64 по Windows; отдельные Play_Su30SM_32/64.bat для ручного выбора. Конфигурация config-su30 с OPENDEMO FALSE и отдельный user-su30 предотвращают запуск демо вместо теста. Старые самолёты сохранены побайтно, общий код обзора изменён намеренно.

## Восстановление

Полный комплект SourcesZIP содержит sources/su30sm-test2/{engine,source,model-source,runtime-template}. Предыдущая версия и история сохранены. Скопировать GameZIP1 в runtime/, GLB в source/su-30sm.glb; установить requirements.txt; применить engine-overrides к полному engine. Запускать последовательно:

```
python model-source/convert.py
python model-source/identical_nozzles.py
python model-source/gear.py
python model-source/flat_shading.py
python model-source/finish.py
```

convert генерирует соответствующий header сопел в engine/YSFLIGHT/src/vehicle/. После генерации собрать движок по инструкции теста1 с включёнными overrides и скопировать EXE. Не подключать идентичный coarse вторым полным DNM:32-битный процесс ранее исчерпывал2GB. В registration ровно4поля: DAT,vis,collision,cockpit.

Архив engine-binaries.zip содержит собранные MinGW32/64 EXE именно этой правки; полный соответствующий движок включён в SourcesZIP. deliver.py воспроизводит новую модель от проверенных Game/Sources1, сохраняет остальных самолётов и публикует три архива только в новый DRAFT. windows_check.py минимально загружает полёт в настоящей32-битной Windows и даёт две команды шасси. STATUS.json — источник ссылок и контрольных сумм.

## Границы проверки

Шасси и двигатель — игровые приближения, динамика от Су27. Нет заявления о точной заводской кинематике или полном отсутствии внутренних контактов. Интерьер упрощённый, стандартные приборы/HUD игры работают; это не копия реальной приборной панели Су30. Слабый выхлоп — прозрачная геометрия, не физическая модель преломления воздуха. NativeWine64 проверяет реальные команды механизмов и ЛКМ/двойнойПробел на Су30 и Су27; общий обзор не ограничен их идентификаторами. Визуальная приёмка пользователем остаётся впереди.

Референсы шасси: https://www.airwar.ru/enc/fighter/su30sm.html и https://www.airwar.ru/image/idop/fighter/su30sm/su30sm-4.jpg. Вид снизу: https://en.wikipedia.org/wiki/File:Russian_Navy,_RF-34013,_Sukhoi_Su-30SM_(49581508706).jpg. Размерного заводского чертежа механизма не найдено; схемы подвесок не считаются чертежами шасси.
